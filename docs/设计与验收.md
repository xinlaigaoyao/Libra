# 设计与验收

“信息系统分析与设计”课程项目，小组成员：肖沁峰、邓皓柏。

这份文档写给要改代码或检查功能的人，包括三部分：系统按什么规则办业务、后端提供哪些接口、动手前列出来要防住的出错情况。用例图、ER 图、时序图在 [系统分析与设计](系统分析与设计.md)。

## 范围和技术

功能按第 7 周 PPT 的六个模块做：登录与权限、图书管理、读者管理、图书检索、借还续借、逾期与违规统计。

技术沿用 PPT 里的方案：原生 HTML / CSS / JavaScript + Flask + MySQL。前端不用框架，也不需要打包。借书规则都由后端判断，前端只负责显示。

一笔业务的完整流程：读者查书 → 出纳员登录 → 检查读者能不能借 → 借出指定的一册 → 查去向或续借 → 归还并判断是否罚款 → 登记缴款 → 统计和操作日志。

## 借阅规则

PPT 没给具体数字，下面是我们定的演示规则：

| 规则 | 内容 |
| --- | --- |
| 借书上限和借期 | 学生默认 5 本、30 天；教师默认 10 本、60 天。可以在读者档案里单独改 |
| 什么时候算逾期 | 按北京时间（UTC+8）的日历日算。到期当天还书不算逾期，第二天开始算 |
| 逾期罚款 | 每天 0.50 元 |
| 续借 | 每笔借阅只能续借一次，在原应还日期上再加这位读者的借期 |
| 不能借书或续借的情况 | 读者证停用、有没交的罚款、有逾期没还的书。借书还要检查是否超出上限 |
| 损坏赔偿 | 污损 10 元，撕毁 30 元，遗失按书价赔。损坏或遗失的书转为“维护”状态 |
| 欠钱还能不能还书 | 能。有欠款不影响还书 |
| 缴款 | 只登记“已线下收款”，不接支付平台 |

一次还书最多产生两条罚款：一条逾期，一条损坏。

## 数据表

完整字段以 `schema.sql` 为准。

| 表 | 存什么 |
| --- | --- |
| staff | 出纳员账号：用户名、显示名、密码哈希 |
| books | 书目：书名、作者、ISBN、分类、出版社、价格、封面颜色 |
| copies | 每一册实体书：藏书号（唯一）、属于哪种书、存放位置、状态（在库 / 借出 / 维护 / 下架） |
| readers | 读者：读者证号（唯一）、姓名、院系、学生或教师、借书上限、借期、是否停用 |
| loans | 借阅记录：谁借了哪一册、借出时间、应还日期、归还时间、续借次数 |
| fines | 罚款：对应哪笔借阅、类型、金额（以“分”为单位存整数，避免小数误差）、说明、缴清时间 |
| audit_logs | 操作日志：谁、做了什么、对哪个对象、什么时间。没有删除日志的接口 |

## 怎样保证数据不乱

借书、还书、续借、缴款都放在数据库事务里，要么全部保存，要么一条都不保存。操作日志也在同一个事务里，所以不会出现“业务办了但没有日志”的情况。

两个人同时操作时：

- 借书时先锁住读者记录，再锁住这一册书。这样同一个读者同时借两本，不会超出上限；同一册书也不会被两个人同时借走。
- 数据库里还有一道保险：同一册书只能有一条“未归还”的借阅记录（用唯一索引保证）。

## 接口

所有接口返回 JSON。成功返回 `{"data": ...}`，失败返回 `{"error": "错误原因"}`，状态码用 400、401、403、404、409、500。

除登录外，所有会修改数据的接口都要先登录，并且请求头里要带 `X-CSRF-Token`（登录后从 `/api/session` 获取）。不登录只能用查书接口，它只返回馆藏信息。

| 接口 | 用途 | 要登录 |
| --- | --- | --- |
| `GET /api/catalog?q=&category=&status=` | 查书，结果包含每一册的状态和位置 | 否 |
| `POST /api/login`、`POST /api/logout`、`GET /api/session` | 登录、退出、查看当前登录状态 | 退出要 |
| `GET /api/dashboard` | 首页概览和近七天借还统计 | 是 |
| `GET /api/books`、`POST /api/books`、`PUT /api/books/:id` | 书目列表、新书入库、编辑书目 | 是 |
| `PATCH /api/copies/:id` | 修改一册书的状态（在库 / 维护 / 下架）。借出中的不能改 | 是 |
| `POST /api/books/import` | 批量导入，一次 1 到 100 行。前端把 CSV 转成 JSON 再提交。只要有一行出错，整批都不保存 | 是 |
| `GET /api/readers`、`POST /api/readers`、`PUT /api/readers/:id` | 读者列表、新增读者、编辑读者 | 是 |
| `GET /api/loans?q=&status=` | 借阅记录，可以查一本书现在在谁手里 | 是 |
| `POST /api/loans` | 借书，提交读者证号和藏书号 | 是 |
| `POST /api/loans/:id/renew` | 续借 | 是 |
| `GET /api/returns/:accession` | 还书前预览：是否逾期、要交多少钱 | 是 |
| `POST /api/loans/:id/return` | 还书，同时登记书的状况，按需生成罚款 | 是 |
| `GET /api/fines`、`POST /api/fines/:id/pay` | 罚款列表、登记缴清 | 是 |
| `GET /api/reports`、`GET /api/audit` | 统计报表、操作日志（最近 200 条） | 是 |
| `GET /api/export/loans`、`GET /api/export/fines` | 导出借阅明细或罚款明细的 CSV | 是 |

## 写代码前列出的出错情况

下面这些是动手之前先想到、需要防住的情况，`tests/e2e.cjs` 里的测试就是照着这份清单写的。

1. **权限**：没登录就看读者资料或改数据；密码错误；CSRF 令牌缺失或不对。
2. **输入**：读者证号或藏书号不存在；字段为空或太长；上限、借期填了不合理的数；读者证号、藏书号、ISBN 重复。
3. **同时操作**：两个人同时借同一册书；同一读者同时借多本，超出上限；有欠款、有逾期或已停用的读者借书。
4. **书的状态**：借出下架中或维护中的书；把借出中的书下架；对已经还了的记录再还或再续借。
5. **重复操作**：重复还书导致重复罚款；重复缴款导致重复记账；还书过程中出错，导致借阅记录和书的状态对不上。
6. **算钱**：到期当天就被罚款；跨天的逾期天数算错；金额有小数误差；前端提交一个假的金额。
7. **续借和还书**：续借超过一次；逾期了还能续借；损坏记录丢失；有欠款就不让还书。
8. **导入和安全**：批量导入中间某一行出错，导致前面的行已经存进去；导出的 CSV 被 Excel 当成公式执行（CSV 注入）；HTML 或 SQL 注入。
9. **界面**：搜索、筛选、没有结果时的提示、错误提示显示不对；手机上页面横向溢出；刷新后数据丢失。

测试用真实的 MySQL、Flask 和浏览器跑，不用假数据或模拟接口，会生成截图、JSON 结果，可以重复运行。没有写单元测试。怎么跑测试见 [README](../README.md#测试)。

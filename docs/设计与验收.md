# 校园图书馆出纳自动化管理系统

课程：信息系统分析与设计。小组：肖沁峰、邓皓柏。

## 设计基线（实现前）

依据第 7 周 PPT 的六个模块实现：登录与权限、图书信息管理、读者信息管理、图书检索、借还续借、逾期与违规统计。技术保持原方案：原生 HTML / CSS / JavaScript、Flask、MySQL。前端不依赖框架或构建器，后端负责业务规则，InnoDB 事务保证状态一致。

业务闭环：公开检索 → 出纳员登录 → 读者资格校验 → 指定副本借出 → 去向查询 / 续借 → 归还及违规判定 → 罚款登记与缴清 → 统计与操作审计。

## 实体与约束

- staff：出纳账号、显示名、密码哈希。
- books：书名、作者、ISBN、类别、出版信息、封面色。
- copies：藏书号（唯一）、书目外键、馆藏位置、状态（在库 / 借出 / 维护 / 下架）。
- readers：读者证号（唯一）、姓名、院系、类型、借阅上限、借期、有效状态。
- loans：读者与副本外键、借阅时间、应还日期、归还时间、续借次数。活动借阅用生成列 + 唯一索引限制同一副本只能有一条。
- fines：借阅外键、类型、金额（整数分）、说明、缴清时间。每次归还最多产生一条逾期和一条损坏罚款。
- audit_logs：操作者、操作、对象、时间、详情，不可通过业务 API 删除。

借出 / 归还 / 续借 / 缴款在数据库事务内完成；借出先锁读者再锁副本，避免同时借出超过上限；活动借阅唯一索引作为第二道保障。操作日志同事务提交。

## 接口契约

统一 JSON：成功 `{"data": ...}`，失败 `{"error": "可读错误信息"}`，错误使用 400/401/403/404/409/500。所有写接口均需登录和 CSRF 请求头。公开目录只返回馆藏信息。

| 接口 | 用途 |
|---|---|
| GET /api/catalog?q=&category=&status= | 免登录检索，包含副本与位置 |
| POST /api/login、POST /api/logout、GET /api/session | 出纳员会话 |
| GET /api/dashboard | 实时概览与近 7 日流通统计 |
| GET/POST /api/books、PUT /api/books/:id | 书目维护、新书与副本入库 |
| PATCH /api/copies/:id | 副本上下架及维护 |
| POST /api/books/import | CSV 内容转换后的结构化批量导入，整体回滚 |
| GET/POST /api/readers、PUT /api/readers/:id | 读者及借阅规则维护 |
| GET /api/loans?q=&status= | 借阅记录、去向追踪 |
| POST /api/loans | 输入读者证号与藏书号办理借阅 |
| POST /api/loans/:id/renew | 未逾期且无欠款时续借一次 |
| GET /api/returns/:accession | 预览归还、逾期与费用 |
| POST /api/loans/:id/return | 归还、损坏登记、生成罚款 |
| GET /api/fines、POST /api/fines/:id/pay | 罚款流水与缴清登记 |
| GET /api/reports、GET /api/audit | 统计与操作日志 |
| GET /api/export/:kind | CSV 报表导出 |

## 规则决策

PPT 未给出具体额度，以下为可演示的课程规则：学生默认 5 本 / 30 天，教师默认 10 本 / 60 天，可在读者档案修改；以 Asia/Shanghai 的自然日计，截止日当天不逾期，逾期每天 0.50 元；续借一次，在原应还日延长该读者的借期；有欠款或已逾期不可新借或续借。污损 10 元、撕毁 30 元、遗失按书价赔偿，损坏副本归入维护状态。缴款仅登记线下收款，不接支付平台。

## 先列出可能失败的情形

1. 未登录读取读者隐私或发起写操作；登录错误；缺失 / 错误 CSRF。
2. 无效读者证号 / 藏书号；空字段、超长字段、非法额度、重复证号 / 藏书号 / ISBN。
3. 同一副本并发借出；同一读者并发越过借阅上限；欠款、逾期、停用读者借书。
4. 下架或维护中的副本借出；借出中的副本下架；归还或续借已结清记录。
5. 重复归还重复罚款；重复缴款重复记账；归还中异常导致记录和副本不一致。
6. 到期当天误罚；跨日逾期天数不正确；金额浮点误差；伪造费用。
7. 续借超次数、逾期续借；损坏记录丢失；归还时欠费阻止收书。
8. 批量导入中间一行错误导致部分写入；CSV 注入；HTML / SQL 注入。
9. 搜索、筛选、空状态、错误反馈不正确；移动端溢出；刷新丢失数据库记录。

验证以真实 MySQL + Flask + 浏览器 E2E 为主，生成截图、JSON 结果与可重复执行脚本；不编写事后单元测试。
